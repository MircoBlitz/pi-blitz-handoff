# T01 — Current-Pi validation

## Authorization

Blocked until the user explicitly approves this real-model, real-session-state gate immediately before execution.

## Validator result

On the final locally validated commit, run a bounded interactive Pi walkthrough proving native source-to-replacement behavior without changing product files.

## Allowed result paths

None. This is a validation task. The orchestrator records approved evidence in `RESULT.md` and plan status afterward.

## Read first

- `docs/specification.md`: supported environment and observable public flows
- final package README
- exact validation commit

## Required scenarios

- Explicit `/sh` or tool start reaches readiness and writer.
- NOT-YET leaves source work available; a later GO proceeds.
- Replacement is genuinely fresh and records source parent lineage.
- First user turn starts with a meaningful session title and contains the dossier.
- Ordered deferred prompts appear as separate sequential inputs in the appended section.
- Successful transfer removes its recovery file.
- One representative cancellation or writer-failure path preserves recoverable prompts.

## Exclusions

No production/customer data, publication, broad exploratory testing, speculative edge cases, source edits, or Git history.

## Acceptance

Each scenario records exact observed PASS/FAIL evidence against the fixed commit. Any failure blocks release and becomes a narrowly scoped forward FIX; the validator does not edit code.
